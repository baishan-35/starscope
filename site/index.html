按标签发现项目

快照只收录有限项目。点项目上的 #标签、从标签云选一个，或直接输入标签，即可实时向 GitHub 查询同类项目，把目录之外的项目也找出来。

在线查询由浏览器直接匿名请求 GitHub 公开 API，本站不接收、不存储任何凭据。匿名额度约 10 次/分钟，繁忙时稍后重试即可。

Methodology

三种指标，别只看一种

累计目录回答「谁攒得多」，涨势目录回答「现在谁在涨」，标签探索负责快照没收录到的长尾。三者都从高到低完整列出。

01 / STOCK

累计星标

按分类从 GitHub Search API 取回项目，每类最多 200 条，按星标从高到低完整列出，不做榜单式截断。适合找成熟、可长期依赖的基础设施，代价是老项目有先发优势。

02 / FLOW

窗口增量

合并 16 张 GitHub Trending 页面，保留日 / 周 / 月全部带真实增量的项目并按新增星标降序完整列出。「涨幅 = 新增 ÷ 总量」让小基数高增长浮上来。

03 / GRAPH

标签扩散

从任意项目的 topic 出发，实时查询该标签下的其他仓库，再顺着「相关标签」继续挖，把快照之外的项目也纳入结果。

「全部」的边界：这里完整列出的是本站已收录的项目（— 个），不是 GitHub 全量仓库——官方单次搜索最多返回 1000 条结果，快照也是定时抓取的。涨势数据仍只是 Trending 的头部切片，涨得快不等于质量好；新星目录的「日均涨星」是创建至今平均值，不是近 30 天净增长。

02 / SOURCE

数据来源与覆盖

累计与新星数据来自 GitHub Search API，涨势数据来自 GitHub Trending 页面的日 / 周 / 月新增星标。快照 2026-11-14 05:11（北京时间）自动生成。每类最多收录 200 条，官方单次查询上限 1000 条结果。

03 / PRIVACY

隐私与凭据

本站无账号体系、无服务端日志、无第三方统计与广告；仅在浏览器本地保存主题偏好。标签探索由浏览器直接向 GitHub 公开 API 发起匿名请求，不收集、不传输任何访问凭据。匿名额度约 10 次/分钟，超限稍后重试即可。

04 / LIMITS

准确性与局限

涨势数据只是 Trending 的头部切片，涨得快不等于质量好；新星目录的「日均涨星」是创建至今的平均值，不是近 30 天净增长。所有数字以 GitHub 实时页面为准，本站不对数据的完整性或时效性作保证。
